## 🔍 问题诊断

### 发现1: Val Dice显著下降

```
V0.3: 0.8239
V0.4: 0.7856
差距: -0.0383 (-4.6%)
```

**原因分析**:
1. **模型容量不足**: 8.5M vs 31.4M (-73%)
2. **提前收敛**: 47 epoch达到最佳 vs V0.3的133 epoch
3. **Dropout过强**: 0.15可能对小模型来说太激进

### 发现2: 过拟合问题确实改善

```
Train-Val Gap:
V0.3: 16.8% (严重过拟合)
V0.4: 8.5% (改善50%) ✅

但这是以牺牲整体性能为代价
```

### 发现3: 训练曲线异常

从training history看：
- Val Dice在epoch 44达到peak (0.7856)
- 之后20 epoch没有significant提升
- Last 10 epochs range: 0.0867 (未plateau)
- 说明模型仍在学习，但进步缓慢

---

## 💡 诊断结论

### 主要问题: 模型容量不足

**证据**:
1. **Val Dice下降4.6%**: 模型学习能力不够
2. **早期plateau** (epoch 47): 容量饱和
3. **Train Dice仅0.845**: 连训练集都无法充分拟合

**对比**:
- V0.3 Train 0.9766: 模型容量足够记住训练数据
- V0.4 Train 0.8449: 模型容量不够，训练集都学不好

### 次要问题: Dropout可能过强

**Dropout 0.15的影响**:
- 训练难度增加1.18倍
- 对8.5M小模型来说可能过于严格
- 建议降至0.1或0.05

## 🎯 改进建议

### 优先级1: 增加模型容量 ⭐⭐⭐⭐⭐

**V0.4a方案**: 中等容量
```python
BASE_CHANNELS = 56  # 介于48和64之间
DEPTH = 4           # 保持
Dropout = 0.1       # 降低

预期参数: ~11M (vs V0.4: 8.5M, V0.3: 31.4M)
```

**理由**:
- 8.5M太小，学不好
- 31.4M太大，过拟合
- 11M可能是sweet spot

### 优先级2: 降低Dropout ⭐⭐⭐⭐

```python
Dropout = 0.1  # 从0.15降低

理由:
- 小模型不需要太强的正则化
- 0.15对8.5M模型太激进
- 0.1更平衡
```

### 优先级3: 延长训练 ⭐⭐⭐

```python
EPOCHS = 250  # 从200提高
PATIENCE = 30  # 从20提高

理由:
- V0.4在64 epoch停止，可能还没充分学习
- Last 10 epochs未plateau，说明仍在学习
- 给更多时间
```

### 优先级4: 调整数据增强 ⭐⭐

```python
# 可能需要更强的增强补偿小模型
A.Rotate(limit=30, p=0.8)  # 从25提高
A.ElasticTransform(alpha=40, p=0.4)  # 从30提高
```
